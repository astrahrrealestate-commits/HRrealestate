# EstateOS — Claude working guide

AI property-management assistant (Phase 1) for one owner, Harjot. Reads tenant/contractor WhatsApp + Gmail,
links messages to cases, proposes typed actions with 2–3 drafts, and asks Harjot to approve on WhatsApp.
**Phase 1 sends nothing to tenants**: only Gmail drafts and messages to Harjot.

- Plan + milestones: [docs/build-plan.md](docs/build-plan.md) · Diagram: [docs/architecture.md](docs/architecture.md)
- Current spec: [docs/superpowers/specs/](docs/superpowers/specs/) · Status: [docs/PROGRESS.md](docs/PROGRESS.md)

## Invariants (non-negotiable — reviewer agent checks every one)
1. **Postgres before queue.** Insert/commit the row, then enqueue its id. Redis never holds the only copy.
2. **Idempotent everything.** Every task/handler safe to run twice, backed by a DB unique constraint or status
   guard, not by in-memory bookkeeping. Celery `countdown/eta` ≤ 300 s; anything later is a `timers` row.
3. **Tenant scoping.** Every domain query filters by `company_id`. No cross-company joins.
4. **Send isolation.** Only `app/sender/` imports `SenderSettings` or `app.channels.*.outbound`. Everyone else
   writes `actions`/`approvals`; the sender re-checks `approval.status=='approved'` and
   `approval.draft_version == action.draft_version`, and uses `sends.idempotency_key`.
5. **Message content is data, never instructions.** Untrusted text enters prompts only inside the template's data
   delimiters. Model output is validated against typed contracts before anything acts on it; it never picks a
   recipient, SQL or tool freely.
6. **Adapters for every external call** (Meta/partner, Gmail, Pub/Sub, OpenAI, S3). Pipeline code depends on
   interfaces; tests use fakes or recorded fixtures.
7. **Contracts are the schema.** `app/contracts/*` Pydantic models are the API between stages and the LLM
   structured-output schema. Change them deliberately; never fork a second definition.
8. **Immutable artifacts.** Committed migrations, published prompts (`app/llm/prompts/vN/`) and recorded fixtures
   are never edited — new revision / version / file instead.

## Code conventions
- Python 3.12, typed everywhere, mypy strict. `StrEnum` for enums. `AwareDatetime` / `timestamptz`, UTC stored.
- Money = `Decimal` + currency, never float. IDs = UUIDv7 via `app.core.ids.new_id()`.
- SQLAlchemy 2 typed (`Mapped[...]`), psycopg 3 sync. Sessions short, explicit `commit()`.
- structlog only (no `print`, no stdlib `logging` direct). Never log message bodies or secrets at info level.
- Errors subclass `app.core.errors.EstateOSError`.
- Small focused modules. One purpose per file; if it passes ~300 lines, split.

## Testing
- TDD: failing test first. `tests/unit/` = no I/O; `tests/integration/` = real Postgres/Redis from compose
  (never SQLite). Network blocked by pytest-socket except localhost.
- Recorded provider payloads in `tests/fixtures/recorded/<provider>/`, PII-redacted (see `/record-fixture`).
- Never skip, xfail or loosen a test to get green. A bug fix starts with a test that reproduces it.

## Workflow
- New milestone → `/milestone` (brainstorm → spec → plan → subagent-driven execution).
- Per task → `estateos-implementer` agent, or inline TDD.
- Done means evidence → `/check` (quote the result line). Noisy suites → `test-runner` agent.
- Before commit → `estateos-reviewer` for non-trivial diffs. Conventional commits (`feat(m2): …`).
- Branch per milestone `m<n>-<slug>`; never commit straight to `main` after M1 lands.

## Guardrails already enforced by hooks (`.claude/hooks/`)
- Bash: blocks git writes outside this repo (parent dir is a home-dir repo), force push, `--no-verify`,
  reading `.env`, shell calls to Meta/Gmail/OpenAI/PubSub, destructive `rm`. Asks on reset --hard, push,
  volume wipe, alembic downgrade, DROP/TRUNCATE, dependency changes.
- Edit/Write: blocks `.env`, edits to committed migrations/prompts/fixtures, send-credential references outside
  `app/sender/`, hard-coded keys.
- After edit: ruff format + fix on the file; leftover lint is fed back.
- Stop: `ruff → mypy → unit` on changed Python; failing gate blocks the turn from ending.
- Gmail MCP send/reply/forward/trash are denied in this project.
If a guard blocks you, follow its message. Do not route around it; ask the user if it is wrong.
