# M13 AI Staff: Categories, Drafting Context, Astra and 90-Day Reload — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Harjot logs in, picks one of six categories, and sees the next actions of that area with the work already
done: drafts he would send (from the whole history, attachments, memory and web research), reviewed quotes, read
documents. Astra can open and search everything. 90 days of mail are reloaded cleanly through the real pipeline.

**Architecture:** Builds on what exists. The pipeline (`app/workflows/pipeline.py`) gets a history mode and reads
attachments, reviews quotes and researches before it drafts. One `Dossier` per mail replaces the proposer's thin
context and feeds proposer `v6` (built on `v5`), owner redrafts and Astra. Six categories replace the old eight.
The category desk is computed from existing tables; no model writes it.

**Tech Stack:** Python 3.12, FastAPI, DBOS 3.2, SQLAlchemy 2, Pydantic AI 2.54, Postgres + pgvector, Next.js.
**Gemini API only** (models, embeddings, Google Search grounding through Pydantic AI's `WebSearchTool`).

**Spec:** `docs/superpowers/specs/2026-11-25-m13-ai-staff-design.md`

**Branch:** `m13-ai-staff` from `m-chats`. Two worktrees: `m13-a` (Dev A), `m13-b` (Dev B); merge into
`m13-ai-staff` at each sync point. (M12 is taken: "Due diligence lite", `docs/PROGRESS.md:107`.)

## Global Constraints
- Categories, exactly: `maintenance`, `finance`, `legal`, `business`, `administration`, `new_projects` (+ internal `spam`).
  Display names: Maintenance, Finance, Legal, Business, Administration, New projects.
- CLAUDE.md invariants hold, above all 4 (`company_id` on every query), 5 (send isolation), 6 (untrusted text only in
  `data_block`; agents have no write tools; recipients from the DB), 9 (published prompts never edited: new versions).
- Related context: same person, same case, unit or lease, company vendor data, company reference documents. Never
  another tenant's mail or documents.
- Web pages are untrusted data, like mail; every research finding carries its URL; no finding without one.
- Send mode stays off. Nothing here sends; drafts still need Harjot's approval.
- **Harjot's drafting standard** (spec, "Drafting standard", verbatim) binds every draft from every path: pipeline
  proposal, owner redraft (`app/pipeline/redraft.py`), Astra, `draft-open`. No generic acknowledgement is ever
  offered as a draft, by the backend or by a screen.
- History-mode mail never creates an action, approval, owner card, feed card, alert, wait, chaser or WhatsApp notice.
- Mail written by Harjot himself (resolved sender is an owner address) is never drafted to.
- Purge needs a preview, a DB snapshot, the worker stopped and a typed confirmation.
- Gemini API key only: every model, embedding and web search; prod refuses any other provider string.
- Quality tier (`LLM_QUALITY_MODEL`, reasoning `high`): proposer, draft research, Astra's research loop, person
  memory. Fast tier (`LLM_MODEL` = `google-gla:gemini-3.8-flash`, current per-agent thinking): everything else,
  including understanding, link check, case summary, doc classifier, doc reader, OCR, quote reader, price extractor.
- Failing test first; `make check` green before each commit; `estateos-security` pass on tasks touching `app/api`,
  `app/sender`, `app/channels`, `app/llm`, prompts or external input.
- Modules < 300 lines, functions < 40 lines (CLAUDE.md). Files this plan grows past that are split in the same task.
